# Non-DOM and canvas hosts

The core has no `document`, no `window`, no `Element`. A host that draws every
pane into one canvas positions from placements instead of mounting an element
per node.

`ContainerHost` is the bridge — it owns one container's layout: viewport,
strategy resolution, the layout run, lock-based affordance suppression, and
affordance dispatch. No framework, no rendering.

```ts
const host = new ContainerHost(store, parentId, registry);
host.setViewport({ w: 800, h: 600 });
const { placements, affordances } = host.layout();
```

The pattern throughout is pure function first, thin DOM wrapper beside it:

| Real API | DOM convenience |
| --- | --- |
| `host.setViewport({ w, h })` | `host.observe(el)` |
| `host.setNaturalSize(id, size)` | `host.observeNatural(id, el)` |
| `host.setScroll({ x, y })` | `host.observeScroll(el)` |
| `insertionIndexByMidpoint(rects, …)` | `childRectsForContainer(el)` |
| `new DragEngine(store)` | `new DragController(…)` |

## Two things a canvas host needs

`.windease-zone` clips its children. Add `.windease-zone--unclipped` to keep the
positioning and container queries and drop the `overflow: hidden`, so one canvas
can span the whole zone.

Placements are in CSS pixels. A `devicePixelRatio` change means every backing
store must be resized, and dragging a window between displays is the common
case:

```ts
const stop = observePixelRatio((dpr) => resizeBackingStores(dpr));
```

It reports the current ratio immediately and again on every change. A resolution
media query embeds the ratio it was built with, so a listener left on one fires
once and is then permanently false; this re-arms at the new ratio each time.

It is deliberately **not** on `ContainerHost`: nothing in `layout()` reads the
ratio, and routing it through the host would notify a canvas host on every
ordinary resize.
