# `stackStrategy`

One child visible, the rest withheld into `unplaced`. This is the tabbed
container.

```tsx
<Zone strategyId="stack" config={{ activeId, headerSize: 28, padding: 4 }} />
```

| Config | Meaning |
| --- | --- |
| `activeId` | which child fills the body; defaults to the first in `childOrder` |
| `headerSize` | pixels reserved at the top for *your* tab strip |
| `padding` | pixels |

<Stack />

## You draw the tabs

The core never measures the strip and never draws it. `headerSize` is an input,
not a measurement — it reserves the band, and what goes in it is yours.
`useStack` gives you the model:

```tsx
const { tabs, activeId, activate } = useStack(stackId);
```

`activate` writes through `store.setActiveChild`, which no lock gates: `arrange`
governs how children are *arranged*, and which tab shows is not an arrangement.

**One trap when you draw the strip.** The stack body is a full-box `<Container>`
overlapping the reserved band, so a strip drawn before it in DOM order swallows
its own clicks. `position: relative` plus a `z-index` above the body is the whole
fix.

Drops can create stacks for you — see
[6.3](/?story=guide--06-drag-and-drop--6-03-tab-stacking).

This is not the `stackStrategy` removed in 0.9.0. That one stacked children
along an axis and `stripStrategy` with `{ axis: 'y', fill: true }` replaced it.
The name was reused.
