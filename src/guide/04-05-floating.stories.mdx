# `floatingStrategy`

A wrapper, not a peer. It places items marked `floating` free over the
container and hands everything else to the strategy it wraps.

```ts
const strategies = { board: floatingStrategy(gridStrategy) };
```

The inner strategy gets the **full** container — a floating panel reserves no
space. Called with no argument, everything floats.

An item floats through its placement bag:

```ts
store.patchPlacement(panelId, { floating: true, snapCorners: ['bottom-left'] });
```

| Config | Default | Meaning |
| --- | --- | --- |
| `inset` | `12` | px from the corner a snapped item rests at |
| `snapThreshold` | `12` | per-axis px within which a corner captures |
| `defaultAnchor` | `'bottom-left'` | corner a newly floated item seeds at |
| `handleSize` | `0` | height of the drag band; `0` makes the whole item the handle |
| `snapToPanes` | `false` | also snap to the corners of the inner strategy's panes |

<HandleBand />

Anchors are sticky: a snapped item keeps its *corner* across a container resize
rather than the pixel position it landed on. Snapping is live during the drag —
there is no drag-end event — so un-snapping moves the panel up to
`snapThreshold` px at once.

<SnapToPanes />

## Two things that bite

**The handle covers what it sits on.** At the default `handleSize: 0` the whole
item is the handle, so its own buttons cannot be clicked. Give it a title-bar
band, or turn built-in handles off and dispatch the drag yourself.

**There is no stacking order in `LayoutResult`.** A floating item renders above a
tiled one only if the host renders it later — register it last, or set a
`z-index`.
