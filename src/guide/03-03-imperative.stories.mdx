# Imperative: `<Container>`, chrome and `<Root>`

The store owns the tree. You mutate it, and React renders whatever is there.

```tsx
const store = new Store();
store.registerNode(createNode({ id: ROOT, container: { strategyId: 'strip', config: {} } }));
store.showNode(ROOT);
```

`<Container parentId>` renders one container's visible children at the
placements its strategy produced, each absolutely positioned. What goes *inside*
each child is a chrome handler:

```tsx
const chrome: ChromeMap = {
  panel: ({ node }) => <div className="pane">{String(node.meta?.title)}</div>,
  group: ({ node, children }) => <div className="group">{children}</div>,
};

<Container parentId={ROOT} chrome={chrome} viewport={{ w: 800, h: 600 }} />
```

Chrome is keyed by `node.kind`, with `'default'` as the fallback. A container's
handler receives its already-rendered subtree as `children` and decides where to
mount it — return without mounting them and the whole subtree is hidden.

## `<Root>`

`<Root store chrome>` mounts a `Provider` and renders every parentless node. It
is the one-line entry point when you have a store and want it on screen:

```tsx
<Root store={store} chrome={chrome} />
```

## Which to pick

Declarative when your layout is a function of app state you already hold.
Imperative when the user's arrangement is the state — anything with drag,
stacking or splitting, because those restructure the tree and JSX would revert
them.
