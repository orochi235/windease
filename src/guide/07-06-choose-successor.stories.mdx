# `chooseSuccessor`

When the focused node is destroyed or hidden, the store picks a successor rather
than dropping focus to the document.

The built-in order: next visible sibling, previous visible sibling, the parent's
remembered child, the parent itself, then the first visible leaf anywhere. `null`
when the tree has nobody left.

```ts
const store = new Store({
  chooseSuccessor: ({ store, departing, reason }) => {
    if (reason !== 'destroyed') return undefined;
    return store.getNode(HOME) ? HOME : undefined;
  },
});
```

## `reason` separates the causes

`'destroyed'`, `'hidden'` or `'moved'`. A consumer plausibly wants a different
successor per cause — closing a tab returns you to the file tree, collapsing one
does not — and branching on `reason` is how one policy covers all three.

Return `undefined` for the causes you have no opinion about.

## `null` means nobody, deliberately

Distinct from `undefined`. `null` leaves focus on nothing;
`undefined` runs the built-in order.

## The store validates the id

A returned id that names the departing node itself, or anything not focusable, is
traced and treated as `undefined`. So a policy that returns a stale id degrades
to the built-in instead of trapping focus on a dead node.

The choice is reported on the `focus.successor` event with the same `reason`, so
a host can react without owning the policy.
