# `gridStrategy`

Uniform cells, filled left to right.

```tsx
<Zone strategyId="grid" config={{ cols: 3, gap: 8, padding: 8 }} />
```

| Config | Meaning |
| --- | --- |
| `cols`, `rows` | fixed counts |
| `maxCols`, `maxRows` | caps for auto-balancing |
| `orientation` | which axis fills first |
| `maxItems` | capacity cap — mutually exclusive with `maxCols`/`maxRows` |
| `gap`, `padding` | pixels |
| `resizable` | emit span seams |

<Grid />

Setting `cols` makes `maxCols`, `rows` and `orientation` dead config. That used
to be silent; grid now declares it through `configConflicts` and it surfaces as
a `layout` trace.

## Spans

A child can cover several cells through `placement.span` — **cell counts, not
pixels**:

```ts
store.patchPlacement(id, { span: { cols: 2, rows: 1 } });
```

`span` is kept separate from `size` so one key never means pixels under one
strategy and cells under another. A span wider than the grid clamps.

## Sizing the grid to its rows

A grid derives its whole tiling from the item count, the spans and the config —
without reading the container. `gridTiling` reports it, so a host can size the
grid itself:

```ts
const { cols, rows } = gridTiling(items, config);
const height = rows * ROW_H + gap * (rows - 1);
```

It lays nothing out and takes no container. Empty items tile to `0 × 0`, so the
height comes out zero rather than one empty row.
