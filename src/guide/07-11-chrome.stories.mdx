# Custom chrome and affordance renderers

## Chrome

A chrome handler draws one node's surrounding UI and decides where its subtree
goes.

```tsx
const chrome: ChromeMap = {
  panel: ({ node }) => <Pane node={node} />,
  group: ({ node, children }) => (
    <section className="group">
      <header>{String(node.meta?.title)}</header>
      <div className="group__body">{children}</div>
    </section>
  ),
  default: ({ children }) => <>{children}</>,
};
```

Keyed by `node.kind`, falling back to `'default'`; no match renders nothing.
`args.children` is the already-rendered subtree — **return without mounting it
and the whole subtree disappears**, which is the usual cause of a container that
renders its frame and nothing inside.

The function form dispatches however you like:

```tsx
<Container chrome={({ node, children }) => …} />
```

## Overlays

`<Container overlay>` draws over the children, given the layout that just ran:

```tsx
<Container overlay={({ placements, draggingAffordanceId }) => …} />
```

For drop indicators and selection rings.

## Affordance renderers

`<Container affordances>` renders the strategy's seams with the built-in
treatment. Passing a function replaces it wholesale:

```tsx
<Container affordances={({ affordances, dispatch, hitPad }) => …} />
```

**Taking this over means owning pointer handling and keyboard operability for
every seam you draw** — the built-in gives you `role="separator"`, the ARIA
values, arrow keys, `Home`/`End` and the join gesture. Reach for it when you need
a different *element*, not a different look; the look is CSS.

`affordances={false}` turns them off entirely, which is how a floating panel gets
its content back
([5.6](/?story=guide--05-drag-and-drop--5-06-floating-chrome-over-a-tiled-zone)).
