# Declarative: `<Zone>` and `<Panel>`

**React only.** The core has no declarative path — there is no way to describe
a tree to `windease` and have it reconcile one. Declaring a tree means
rendering these components; everything else in this guide works either way.

The JSX owns the tree. Declare a panel and it is registered and shown; stop
declaring it and it is destroyed.

```tsx
<Zone id="dock" strategyId="strip" config={{ axis: 'y' }}>
  <Panel id="files" />
  <Panel id="outline" />
</Zone>
```

Sibling order in JSX becomes `childOrder`. Props like `meta`, `hints`,
`placement` and `lock` are reconciled on every render — change one and the store
is updated; drop one and it is removed.

`<Panel>` needs a parent, from enclosing JSX or an explicit `parentId`. Without
one it throws with a message saying so, rather than silently making a root.

`<Zone>` used without `parentId` is a root. Given one it nests — that is how a
group is expressed, and why there is no `<Group>`:

```tsx
<Zone parentId={rootId} kind="group" strategyId="strip" />
```

## The cost of JSX ownership

Reconciliation runs every render, which means **a gesture that writes what a
prop declares will be reverted on the next render**. Declare `placement` and a
seam drag is undone; declare children and a drop that reparents one is undone.

That is not a bug to work around but a fork to choose:
[3.5](/?story=guide--03-building-the-tree--3-05-who-owns-child-order) covers
handing specific decisions back.
