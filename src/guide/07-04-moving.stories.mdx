# Moving a pane without a pointer

`Shift` plus an arrow rearranges rather than navigates. The pane takes the slot
of whatever that arrow would have moved the caret to — **a reorder when that node
is a sibling, a reparent when it lives in another container**.

The same resolution backs both gestures, `navigate?` overrides included, so a
strategy that customises navigation customises moving for free.

<MoveWithShiftArrow />

Focus rides along with the pane, and the move announces itself
([7.5](/?story=guide--07-keyboard-and-focus--7-05-announcements)).

## A move that cannot happen does nothing at all

The key is inert at the edge of the tree, on a `move`-locked pane, into an
`accept`-locked container, out of a `dragOut`-locked one, inside an
`arrange`-locked parent, or anywhere that would put a node inside itself.

Silence, not an error — which is the right behavior for a key press and the
reason `resolveMove` returns `null` rather than throwing.

**Core**

```ts
const plan = resolveMove({ store, from: store.focusedId, direction: 'right', geometry });
if (plan) applyMove(store, plan);
```

Split in two on purpose: a host can show the destination, gray out a menu
command, or refuse the move before anything is committed.

```ts
type MovePlan =
  | { kind: 'reorder'; id; parentId; at }
  | { kind: 'reparent'; id; fromParentId; parentId; at };
```

Plans go stale. A tree mutated between resolve and apply may reject the plan or
move the node somewhere it no longer describes — resolve immediately before
applying.
