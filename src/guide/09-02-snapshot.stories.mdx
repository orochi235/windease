# Snapshot and hydrate

```ts
const snap = serialize(store);
localStorage.setItem('layout', JSON.stringify(snap));

const store = deserialize(JSON.parse(localStorage.getItem('layout')));
```

JSON-safe throughout. `version` is checked on read and a mismatch throws rather
than being migrated silently.

## What is deliberately not in it

- **Destroyed nodes.** Gone is gone.
- **Transit state.** A move in flight is not worth restoring
  ([8.2](/?story=guide--08-state-machines--8-02-transit)).
- **`container.lastFocusedId`.** Session state, not document state.
- **Measurements.** `hints.sizing` persists — it is intrinsic advice — but the
  measured `natural` size never enters a snapshot and is re-measured on mount.

Capability machines flatten to their current state name and are rebuilt on
hydrate.

## Snapshots read truth

Under a throttle policy, `serialize` reads `nodesTruth`, not the published view.
So persistence and undo are unaffected by pacing — you never save a
half-published tree
([10.1](/?story=guide--10-performance-and-diagnosis--10-01-truth-vs-published)).

## What round-trips for free

`meta`, `lock`, `hints`, `placement` and `container.config` are all ordinary
fields. That is why a collapsed pane
([4.5](/?story=guide--04-resize--4-05-collapsing-a-pane)) and a seam-dragged size
survive a reload with no extra work: a seam drag writes `placement.size`, and
`placement.size` is just a field.

There is no separate strategy-state persistence problem for the built-ins for the
same reason.
