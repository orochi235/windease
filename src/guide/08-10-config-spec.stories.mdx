# `configSpec` and `configConflicts`

Two declarations that turn silent misconfiguration into a trace.

## `configSpec` — what keys mean

```ts
configSpec: {
  axis: ['x', 'y'],
  gap: 'number',
  fill: 'boolean',
  activeId: 'string',
}
```

Catches an unknown key, a misspelled enum value, and a string where a number
belongs. Without it, a typo falls back to the default and the strategy looks like
it is ignoring a setting for no reason.

`checkStrategyConfig` is the check, run by `ContainerHost` on every layout.

## `configConflicts` — keys that cancel each other

`configSpec` cannot express this, because each key is individually valid.

```ts
configConflicts: [
  { kind: 'exclusive', keys: ['maxItems', 'maxCols'] },
  { kind: 'ignored', when: 'cols', keys: ['maxCols', 'rows', 'orientation'] },
]
```

Two shapes. **`exclusive`** keys cancel each other. **`ignored`** marks a key some
other key's branch never reads.

Grid declares both. Setting `cols` has always made `maxCols`, `rows` and
`orientation` dead config — that was silent until it was declared.

## Reading the output

Both report through the `layout` trace category:

```sh
WINDEASE_TRACE=layout npm test
```

```js
localStorage.setItem('windease.trace', 'layout'); location.reload();
```

They never throw. A misconfigured container still lays out — with the default the
typo fell back to — because a config warning should not take down a UI. The trace
is how you find out.
